# AI, Skill, And Workflow Division

This project separates uncertain reasoning, fixed project knowledge, and deterministic automation.

## AI Owns

- semantic understanding of task books
- experiment plan generation
- code generation
- one debug attempt from real stderr
- report writing from real evidence
- semantic quality evaluation
- ambiguous task classification
- complex error explanation

AI must not claim that code ran, screenshots exist, or DOCX structure was preserved unless the workflow recorded real evidence.

## Skills Own

- fixed engineering workflows
- DOCX original-format preservation rules
- real screenshot integrity rules
- sample-library regression rules
- Supabase Storage metadata conventions
- runner boundary rules
- browser screenshot workflow
- report quality evaluation workflow
- multi-agent division rules

Skills are long-term project memory. They should stay concise and point to reference docs when details grow.

## Automatic Workflows Own

- file upload
- file role inference
- document parsing
- code execution
- stdout/stderr/exitCode/runtime capture
- command screenshot generation
- browser screenshot generation
- Supabase Storage upload
- metadata writes
- DOCX patching
- sample-library checks
- lint/build
- future CI regression

## Core Rule

Uncertain, semantic, generative work goes to AI. Deterministic, repeatable, verifiable work goes to workflow code. Fixed project experience and constraints go into skills.
